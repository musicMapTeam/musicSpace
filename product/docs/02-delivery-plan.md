### B. 房间版：Node + SQLite

用途：局域网演示、两台设备的真实交换、视频录制。**是否上线托管待决定。**

- **运行**：`npm run build` 后 `npm start`，同一个 Node 进程提供页面（含 `ai/`）与 `/api/live`；默认只监听本机，手机要访问需 `HOST=0.0.0.0` 并用电脑的局域网地址。服务对文本与 `ai/` 做 gzip，对 `/ai/` 发 ETag 并支持 304。
- **局域网页面是纯 http**：浏览器没有 Cache Storage，AI 文件只能靠 HTTP 缓存（服务的 ETag / 304），在手机上管不管用没有实测，最坏每次重新下载约 10–23 MB；只有 https 或 `localhost` 才会留住。录视频前先想好怎么避开等待，且不掩盖「首次需下载模型」。
- **上线托管的要求**：Node 24+、持久磁盘或 Docker volume（单实例 SQLite，不用临时文件系统，不把多个实例各自的库当共享库）、前置反向代理提供 HTTPS；数据库目录不进 Git、镜像或公共静态目录。房间邀请码只限制房内数据，不能替代站点访问控制，需要限制整个站点时在入口配置访问门槛。
- **现状**：没有选定主机，没有购买或部署。`Dockerfile` 存在，但镜像没有构建成功：拉取 `node:24-alpine` 元数据 7 分钟无返回，已中止；只在临时目录里用同一文件集模拟了构建阶段与运行阶段。房间版只在同一台电脑的两个来源（`127.0.0.1` 与 `localhost`）之间走过，没有两台设备，也没有 HTTPS。
- 官方决赛要求作品「成功部署上线」；若入围，这件事到时必须解决。

## 5. AI 怎样表述

- **产品里的 AI 只有一个**：端侧的视角建议——看一张照片，建议它拍的是舞台、人海、身边还是细节。配对、排序与理由是普通规则，不称模型推理，也不写「AI 匹配」「智能推荐」「契合度」。
- **文案**：「AI 在本机判断，照片不上传」（房间页：判断时照片不上传，保存现场卡时才上传照片）。不说准确、不说确定；75 张公开图上的数字（[产品方案](01-product-plan.md) §3.5）不当作产品指标。
- **为什么放进产品**（回应 FAQ Q1「AI 用得对不对」）：规则做不到「看图判断视角」；放在端侧不产生 API 成本（Q6 没有 token），照片不出设备，可关、可改，失败时不影响任何流程。这是我们的设计理由，不是「有 AI 就有竞争力」的论断。
- **开发过程**：使用 AI 编程工具完成方案、界面与代码（本仓库提交带 `Co-Authored-By: Claude Opus 5.5`；更早的材料另记 Codex、WorkBuddy 等，以团队核对为准），团队负责筛选、修改与验证。FAQ Q3 允许 AI Coding，初赛侧重创意与方案；这不推出作品已有竞争力。未实际使用的工具不列。
- 端侧模型的来源、许可与复现方法见 [`scripts/ai/README.md`](../../scripts/ai/README.md)；这不是我们训练的模型，只做了抽塔、int8 量化与四组视角文字向量的预计算，没有微调。

## 2026-09-30 追加：Avatar Studio 共创主线

用户的新方向是 avatar 为持续身份的音乐社交创作，而不只是两张卡的交换。第一版围绕一个完整双人闭环：创建稳定外观 → 放入照片或原创虚构场景，调整位置/大小/动作 → 私密邀请 → 对方用自己的分身及回应加入 → 发起者接受当前版本 → 双方分别同意后保存作品。

原有 0.16 樱下现场、端侧 AI、「同一刻」与双联仍保持独立入口，不在本轮删除或伪装成 avatar 的模型能力。新主线采用真实 Three.js 三渲二场景与原创可组合几何人物，保留明确标注的矢量轻量降级。六套搭配只是起点；发型、眼镜、上装、下装、鞋履、配件与各部位配色独立，跨场景、邀请与导出保持同一份身份快照。不声称实时 AI 生成、照片自动遮挡或真实艺人参与。音乐为三段可试听的原创程序声景。

实现与验证分层记录：`web/avatar/` 是同仓库独立前端，`server/avatar-*.js` 是 Node/SQLite 私密双人 API，`runtime-preview/` 提供相同权限契约的 Worker+D1/R2 托管适配。浏览器草稿仅在本机；共同作品由服务持久化。持有邀请链接的人可预览被邀请的这张作品，不能读取其它作品；双方是不同的匿名身份，任何内容变化会撤销旧版本的确认与导出许可。

状态、实际测试及尚未完成项以 `docs/avatar/QA.md` 为准。自动测试、浏览器操作、托管部署与实体设备分别记实；不把代理测试冒充目标用户研究，不承诺获奖。
