# 私聊同身份多标签恢复 · 候选修复

2026-10-01。管理 QA 包 `bfdd650` 保持冻结；本项是其后的可靠性修复，实际浏览器双标签验收仍待进行。

只读复现确认旧共享 JSON 的丢失：两个相同身份控制器分别向不同朋友发送，回应都丢失，两个界面都声称已持久保存，但重载只能恢复一个原键。不是跨身份读取，也不是服务端重复存消息。

修复为每项原操作独立的恢复记录；保留旧 v1 读取与兼容快照。已结束的小标记只含身份/对象/操作及草稿编号，不含消息正文或重试键，防止旧快照复活已处理操作。草稿按身份和对话独立保存；发送成功只结清提交时那个草稿编号，另一个标签之后输入的内容（包括相同文字）不会被旧回执清掉。明确失败记录移除不等于消息发出，不清掉未发送草稿。

实际 Node HTTP+SQLite 三身份测试通过：同一发送者两个控制器、两段不同对话、两次真实服务提交后丢回应、重载均找回原键、分别重试仍每段只有一条消息；两个较新草稿均保留。旧兼容快照再写入不能复活已完成操作。另测同一对话较新/相同文字、已拒绝消息的草稿、配额失败时的本机内存草稿保留。

已有聊天+客户端+界面提示检查53项通过，最后的草稿编号收紧后相关3项再次通过。原跨身份切换、原操作预检断网、原文幂等、未读/实际展示才确认、好友/屏蔽和分页回归仍保留。

随后补充临时存储失败的交叉检查：第一条消息已保存而回应延迟，用户编辑下一条时本机存储暂时不可写，恢复后再收到旧成功回应。旧实现会在重新打开对话时丢掉后写草稿，已实际复现并修复；恢复存储时一并持久保存仍未保存的明确编辑，不让旧成功回应把它标成已保存却漏写。完整聊天控制器27项检查通过，包含重开和重载、服务器仍只有原来一条消息。

未声称真实浏览器双标签、混合旧新页面长期同时编辑或物理手机已验。更新本地演示时应关闭旧页面，再打开新版本；已有身份和服务数据保留。完成标记的长期容量治理属于后续生产化事项，本片优先确保未确认消息的原键不丢失。
