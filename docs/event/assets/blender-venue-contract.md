# Music Space 场馆资产交接 · 2026-09-30

目的：用 Blender 精修场馆资产，接入现有 Three.js 房间，保留二维手绘人物、实时换装、照片权限和私聊。当前系统用程序建模，还没有GLB加载适配；下列节点/材质名是新资产的约定，不是已经存在的接口。暂不改动运行中的应用和业务代码。

## 空间与比例

一 Blender 单位对应一 Three 单位，不二次缩放。它是风格化设计单位，不要将人物强行还原为1.7米。角色可见高度约3.1、脚底约y=0，立绘平面包围盒1.5552×3.24。

以下坐标全部是最终glTF / Three坐标：+Y向上，+X是正面对舞台时的右侧，+Z朝观众入口，舞台在-Z。Blender工作坐标换算为(x,y,z)=(Three.x,-Three.z,Three.y)；标准glTF导出会转换回Y-up，不要再手动旋转场馆90度。根节点MS_VENUE_ROOT应位置0/旋转0/缩放1，应用网格物体的旋转/缩放后导出。

现有空间是开前脸的剖视场馆：地板约x[-7,7]、z[-5.55,6.95]，水平视觉地面y=0；后墙z=-5.56、高6.1；右照片墙x=6.97，内侧约6.79。舞台实体中心(-.1,.295,-3.29)、尺寸(9.85,.61,4.28)，完成面y≈.64。允许精修形体、幕布、舞台设备与装饰，但不要占用人物脚点、照片展示区和既定机位视线。

现有固定人物脚点、相机数值与照片区域在anchors.json。手机最多先画4人、桌面8人，人数和衣服始终来自真实成员数据。GLB不要内嵌假观众、角色立绘或用户照片。

## 必留的节点与区域

- MS_VENUE_ROOT：整体根节点；静态结构可合并以减少draw calls
- MS_FLOOR：脚底水平面附近，人物仍由网页单独渲染；不要在脚点放台阶或道具
- MS_STAGE：现有舞台范围，可优化轮廓与实际设备模型；建议减少无意义重复零件
- MS_GALLERY_ANCHOR：空节点，Three位置(6.795,2.64,-.65)、Y旋转-π/2；局部+Z朝房间内，局部+X沿世界+Z。照片框和授权照片纹理由网页动态生成，GLB只做周围墙面/灯具，保留约宽3.6×高4.6的清晰区域
- MS_FOREGROUND_CUTAWAY：靠近镜头的桁架等可隐藏装饰独立成组；照片阅读机位可将这一组隐藏，返回恢复，不能将整面墙或用户照片烘焙到该组
- 可选MS_LIGHT_*、MS_CAMERA_*：仅用空节点记录艺术建议。实际灯光和响应式相机仍由网页控制，不直接采用导出相机比例

照片墙目前每格中心距1.12×1.46，真实外框.965×1.285×.036；手机2列、桌面3列，最多6张，动态按实际张数居中。必须保留该区域、避免柱子/灯架插入照片阅读机位；不要烘焙6张重复示例照。照片为空时不会出现虚构用户图。

## 材质与输出兼容

现有Three r186使用sRGB输出、NoToneMapping、MeshToonMaterial色阶+轻微深度描边/FXAA。不修改已许可的Sakura源码。新资产以干净几何、少数高质量材质为主；酷感来自形体/灯光/构图，不靠全屏色滤镜。

交接GLB使用通用Principled BSDF的基础色/纹理、粗糙度参数，或明确的KHR_materials_unlit。程序化噪声/复杂节点不会直接进入网页，需烘焙为自含纹理。材质名CEL_*供网页加载后转换为现有cel材质；UNLIT_*供字牌/海报保色；EMISSIVE_*为小面积发光灯罩。这个名称映射需要网页集成实现，本次建模不要猜改业务。

深墨#1a1a22、乳白#f1eee4、低饱和紫#393244，黄绿#dced60只做少量强调。二维人物自身是alphaTest/depthTest/depthWrite开启的保色面片，不会接收实体灯影；场馆亮暗要衬托它，不要依赖重打光让人物可见。

网格有正确法线和适度倒角；用几何形成舞台、墙体和设备体积。避免平行重叠面产生z-fighting，不用一张全景画代替场馆。字牌可用原创图形/合法本地字体，贴图嵌入GLB，禁止热链资源。透明材质尽量少；大面积透明雾与光束必须可单独关闭。

首版目标预算：静态场馆约80k三角形以内、50个可渲染网格以内、12个材质以内，贴图一般≤2048；GLB尽量≤5MB。它们是可调整预算，不是现有性能保证。暂不用Draco/KTX2等需要新增解码依赖的压缩。不要打包外部路径、私人照片或未知授权资源。

## 机位与交互约束

全景/人物/照片墙的同一空间转换约950ms；reduced-motion立即到目标。手机390×844需要同时看见主角全身和场景层次，脚不要落进底部约125px的导航/操作区域；顶部标题区也要留位。不能只检查Blender横屏渲染。

人物近景为脚点p+scale*(.6,2.65,7)，看向p+scale*(0,1.65,0)。照片机位位置与张数/屏幕纵横比共同计算，具体公式在anchors.json。全景固定值是目前通过遮挡检查的基线，可提供艺术优化建议，但网页集成后要重新390宽/桌面三机位检查。

## 需要交付

一个完整资产包：musicspace-venue.blend、musicspace-venue.glb、生成/整理脚本（如有）、asset-manifest.json（节点、贴图、材质、三角形/网格/材质数量、原创或授权来源）、正面/人物机位/照片墙三个预览。提供Blend视图只算资产预览；最终须导入实际网页验证视差、深度遮挡、响应式机位、2D角色朝向、照片墙与交互命中。

本包两张截图来自当前真实GPU测试，仅用于对齐尺寸和人物风格，不是新场馆的视觉质量目标。不要修改其上的系统界面、真实成员数据或网络协议来迁就模型。
