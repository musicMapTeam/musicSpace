# Music Space 实施说明 · 文档3.1

产品入口为 `/event-room/`。Web场馆、二维角色与纸件界面共用后端许可；前端展示或隐藏不能替代服务端授权。Node与Worker共用 `runtime-preview/src`，叠加式drizzle迁移随运行包完整提供，持久存储不可省略。

## 入场与近场

共享模块 `runtime-preview/src/admission-protocol.js` 验证唯一场次或社群邀请码、同源正确路径和无额外参数的网址。拒绝跨站、混合目标、凭据、重复参数、片段、控制字符与不合法长度。完整链接与手填邀请码均只打开预览。

Node/Worker兼容预览及明确加入别名，复用既有同意、幂等、关闭和移除检查。社群加入使用预览确定的对象。加入现场不自动加入社群，不授予好友或照片读取权。

二维码、NDEF URI和原生GATT UTF-8值使用同一完整网址。NFC标签写入仅由主动操作启动，重复点击不重复执行，关闭、取消、切换或离开页面中止待完成操作。原生适配只返回待预览网址；宿主应用的广播、扫描、权限及生命周期必须独立实现和验收。

## 共享内容与失败处理

现场照片只通过许可检查后的私有响应读取；撤回、删除、移除与屏蔽不能因群聊或近场连接绕过。双向好友文字私聊保留明确关系状态。长期社群、聊天室及世界杯读写使用独立许可和幂等操作，手动重试原请求，不在断网恢复时自动发送。

本地试穿只预览，明确保存才更新小人。纪念卡只选本人合法可用素材，署名和本人形象必须明确；生成前后复核权限，显示成品预览，取消及旧页面离开释放资源。

下一双人创作角须双方主动参与，各自编辑本人成果，检测并发冲突；编辑使旧确认失效，双方确认同一版本后各自显式保存。素材失效、撤回或屏蔽不得继续读取或导出。该阶段尚未实施。

## 检查与边界

修改先独立分支和草稿PR，必要软件检查、自审及精确提交CI通过后合并；实际发行包单独核验文件一致性、启动、重启和权限。测试使用匿名合成身份，不提交私人照片、凭据或本机证据。原生适配源码未编译或签名，设备互通、实体手机和真实观众仍待外部验收。
