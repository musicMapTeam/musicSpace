# 两张照片的定向交换 · 后台合同

2026-10-01，开发中的下一切片。当前两个浏览器候选保持冻结；本合同不表示新界面或真实屏幕流程已经完成。

## 用户做出的选择

发起者点开本场另一人当前放到照片墙的照片，再选择自己在同场拥有的一张。请求固定两张不可原地改写的 photo ID、双方身份以及审阅的 revision；发送者还明确同意“对方接受后可在线读取我的这张原图”，不能只有预览同意就释放原图。换图必须重新申请。不会自动添加好友，也不复制原图到对方私库。

私藏照片用于发起时，需要本人明确提供一份小图预览：JPEG、每边最多 320px、最多 32KiB，去除元数据、存于原有私有照片存储。只有请求双方可以按状态读取。原图不因 pending 请求而经交换接口公开。

预览来自发起者客户端。服务端只做结构、尺寸和大小校验，不具备像素解码器，因此不能声称已验证预览像素确实对应原图。正式界面应从所选原图直接生成预览并让发送者审阅，接受者可在明确接受后读取这两个指定 ID 对应的原图。上线前需再审这项预览真实性限制。

接受时必须明确展示两人和两张图，说明该选择授权双方在散场后继续在线读取。每一步都有明确同意，不把等待、关闭面板或原操作重试当作同意。

## 权限分开

| 操作/状态 | 照片墙 | 本次交换 |
| --- | --- | --- |
| 发起待回应 | 原墙权限不变 | 双方可按规则看独立小图预览；交换原图仍未授权 |
| 接受 | 原墙权限不变 | 一次原子转换建立双方各自读取指定原图的权限 |
| 从墙收回 | private，不再向全场展示 | 取消涉及该图的 pending；accepted 保留 |
| 主动离场 | 自己的墙分享收回 | 本人与该场的 pending 取消；accepted 保留 |
| 结束/过期场次 | 沿用当前成员照片规则 | 不再新申请；已有 pending 在自身有效期内且双方仍在场时可回应；accepted 保留 |
| 任一方撤销一次交换 | 不变 | 对等结束本次双方在线访问，不删除任一原件，不改变其他独立交换 |
| 收回一张图的全部分享 | private | 原子取消该图的全部 pending、撤销全部 accepted；相关交换的另一向访问也结束 |
| 删除照片 | 原图删除 | 全部相关交换结束 |
| 屏蔽 | 沿用原屏蔽规则 | 这两人所有场次的 pending/accepted 同事务结束；取消屏蔽不恢复 |
| 移除好友 | 不变 | 已明确接受的交换不因朋友关系变化而撤销 |

“撤销”只阻止之后的服务读取。已下载、截图或已发送到浏览器的内容无法远程收回，不承诺公平交付或删除对方副本。

## 状态和接口

状态：pending、accepted、declined、cancelled、revoked；pending 24 小时失效，读接口可返回有效状态 expired，不依赖定时清理才断权。终态不复活。每对人每场最多一个有效 pending；同一具体照片对不重复建立活跃授权。

接口位于 `/api/event`，复用当前匿名身份和幂等操作机制：

- `POST /rooms/:roomId/exchanges`：recipientId、offeredPhotoId、requestedPhotoId、两张 revision、offerPreviewConsent、offerOriginalConsent、offeredPreviewDataUrl
- `GET /exchanges`：24 条参与者记录分页；`GET /exchanges/:id`：当前真值
- `POST /exchanges/:id/accept`：revision、exchangeConsent；decline/cancel/revoke：revision
- `GET /exchanges/:id/preview`：小图预览
- `GET /exchanges/:id/photos/:photoId/image`：已接受后的指定原图
- `POST /photos/:id/withdraw`：revision，收回这张图的全部分享

照片墙原图片接口和 `recap.photos` 不扩权。“交换过的视角”后续使用独立集合。主办方不因此取得任何私藏或定向图片权限。

同意、隐私操作和回执必须同事务；隐私关闭不依赖预读的交换 revision，避免晚到接受从删除/屏蔽/全部收回中漏出。图片对象读取后再次核对当前权限和同一存储键，再返回字节。历史幂等回执不是当前授权；重放旧 accepted 不能复活访问。

## 界面接入前的硬性检查

- 全面检查 `visibility === 'private'` 的文案：有定向授权时，不能称“仅自己可见”。应区分“照片墙：不展示”和明确的交换对象
- 发送前展示独立小图及对象，说明何时可看到原图；接受前说明两张指定照片、散场权限、对等撤销和已保存副本边界
- 提供清楚的“从照片墙收回”“撤销本次交换”“收回全部分享”三个不同动作
- 显示结果未知时先确认原操作，不把“停止等待”写成已撤回
- 缓存按当前身份、交换、照片和授权版本隔离；切身份或撤销时清理 DOM 和对象 URL
- 使用原图库与已拥有的照片，不自动替人上传、交换或加入新的场次

当前只实现后台和源层合同检查；在接 UI、浏览器验收之前，不计作可用交换功能交付。

后台验收（2026-10-01 08:28 UTC）：102 项交换合同、114 项既有房间/照片/好友/私聊/回顾回归通过。覆盖 Node HTTP+SQLite 和 Worker 经本地 D1/私有对象适配器的行为，不是已部署的 Cloudflare 验收。独立审阅发现并修复了等待跨过截止时间仍可接受的问题：期限在事务执行时以 SQLite/D1 内置时钟判定，晚到的接受不会复活已过期请求；创建在照片存储或事务等待跨过场次到期时也拒绝。旧 0000–0003 迁移保持原样，新表通过叠加迁移创建。

## 预览保留边界

后台首片会保留请求关联的受保护小图对象，终态只切断在线读取；没有声称撤销即物理擦除这些衍生字节。原图删除仍按既有安全提交后清理流程执行。预览的物理保留/清理政策需在完整产品收口时明确，不能绕过未知提交结果盲删存储。
