# 现场原操作恢复 · 同身份多标签修复

2026-10-01，接在已经实际验过的管理候选之后，尚待真实浏览器多标签检查。只修持久恢复，不新增功能。

真实 Node HTTP 复现旧问题：同一匿名身份在两个控制器打开两个场次，分别上传照片；两次服务提交成功，仅丢掉回应。两个界面都说原操作可恢复，但重载只能找回一个原键。服务中的两张原件没有丢失；风险是用户无法再准确确认另一项操作。

新格式按每个操作独立保存精确请求目标、正文与原键，旧共享快照仍可读。已结束操作留下不含正文、图片或原键的小标记，旧标签写回旧快照不会复活它。关闭页面不再回写整个旧快照。新请求必须先持久保存恢复记录，存储不可用时保留当前草稿并停止发送。

实际 Node HTTP/SQLite 检查通过：两次已提交回应丢失后，两项都能重载并用相同原键、正文、场次重试；最终仍只有两张原件，新选照片草稿保留。旧共享快照重写不能恢复已结清操作。存储满时没有发出新上传，恢复后按原操作只增加一张。相关原有场次、照片、社交、回顾和身份隔离检查一起通过。

这不等于真实浏览器多标签已经验过，也不保证两标签同时编辑同一份本机照片草稿会自动合并。照片原件在服务按权限保存；尚未提交的选图仍是当前设备草稿。混合旧版和新版页面长期并行不在本轮支持范围，更新包时应关闭旧页面后再打开。完成标记长期容量管理属于后续生产化事项。
