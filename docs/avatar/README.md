# Avatar Studio · 给你留个位置

持续的分身身份、可控的音乐场景、需要另一人真正回应的共同作品。

## 已实现的范围

1. 创建昵称，从六套原创搭配开始：留白、断拍、循迹、回声、失真、脉冲。可自由组合 8 种发型、6 种眼镜、6 件上装、6 种下装、4 种鞋履、6 类配件，以及独立配色、4 种表情和 4 种动作；换一件保留其它选择。实际三渲二几何人物跨场景保持身份，WebGL 不可用时明确标记 2D 轻量回退
2. 从三套原创虚构片场或本人照片开始，选择三段原创声景之一；手动拖动、键盘微调、比例、角度与四种姿态
3. 本机私密草稿、撤销/重做、作品收藏、单人 1440×1920 PNG
4. 创建私密邀请，另一个独立身份预览后明确同意加入，用自己的分身与一句回应改变作品
5. 发起者确认当前版本，双方分别允许保存后才能导出共同 PNG。修改任何内容都会撤销旧确认。对方可退出，邀请可关闭/重新生成
6. 待提交修改本机保留、幂等重试、乐观锁冲突提示、身份持久化与存储不足提示

「月白」是原创虚构音乐人，只用于想象同台创作；真实朋友加入时使用自己的身份。没有冒充艺人回应、真实合照或代言。

## 运行

Node.js 24：`npm ci` → `npm run build:all` → `npm start`，打开 `/avatar/`。

旧主页、端侧 AI 模型、原有现场与双联路径保持不变。匿名身份不能通过昵称找回；清空浏览器数据会失去原身份。不要随运行包分享 data/、数据库或真实用户照片。

`dist/avatar/index.html` 可作为静态文件单独打开；这是本机创作模式，真实双人邀请需要服务端。跨设备访问 Node 服务需要同一网络可访问的地址；127.0.0.1 只代表当前设备。公网运行应使用 HTTPS 与持久存储。

## 托管适配

`runtime-preview/` 与 Node API 保持相同端点和权限逻辑：D1 存储结构化数据，R2 照片经认证路由按需读取。首次迁移由 Drizzle 生成，部署后不改写已应用迁移。托管预览是同一个 MusicSpace 功能的交付通道，原 GitHub Pages 根入口不被替换。

## 验证

- `npm test`：保留并验证 0.16 的原有规则与 API
- `npm run test:avatar`：Node API 与前端状态回归
- `npm run test:runtime`：SQLite-backed D1/R2 适配器测试，不能替代真实托管验证
- `npm run build:all && npm run ai:check`：构建两个入口并检查旧 AI 资源完整性

实际结果与浏览器验收范围见 [QA](QA.md)。
