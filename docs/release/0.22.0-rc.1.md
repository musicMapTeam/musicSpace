# Music Space 0.22.0-rc.1 — 路线 B：浏览器内示例站与照片视角 AI 预发布

这一版把「同一刻，另一面」的照片流程接回现场房间，并让 GitHub Pages 能承载一个不需要服务器的示例站。

- **照片流程**：放照片时，在本机压缩之前从原图读出拍摄时间（EXIF）；端侧 AI（TinyCLIP 图像塔加 onnxruntime-web，模型文件来自本站）只给出视角建议，没把握就写「不确定，请选择」，选择永远由人做。照片墙把拍摄时间相差不超过 3 分钟的照片分成「同一刻」，在另一视角的照片上标「同一刻的另一面」并写出理由，交换申请里推荐用哪张照片交换。分组、配对、排序和理由是规则，不是 AI。拍摄时间、视角和各自的来源（时间来自照片自带信息或本人填写；视角来自本人选择，或本人保存时没有改动的 AI 预选）随照片保存：迁移 0013，四个可空新列，旧库照常打开。
- **示例站**：房间服务（同一份 `event-worker.js` 与 `avatar-worker.js`）在浏览器页面里运行，SQLite 用 sql.js，照片放在 IndexedDB，没有服务器，什么都不会上传。同场的四位「·示例」角色是虚构的，由页面里的程序用普通接口自动回应，所以一个人就能走完整个流程。
- **构建与发布工具**：`npm run build:pages`、`npm run preview:pages`、`npm run test:static`，以及 `scripts/pages/` 里的校验与发布脚本：先发预览，经用户同意后一次性切换，不 force push。
- **手绘涂鸦风**：房间页和三维场馆改成「米色点阵纸上的马克笔涂鸦」：墨线手绘边框、硬边错位阴影、粉 / 薄荷 / 黄马克笔点缀、贴纸、胶带、拍立得照片和叠层大标题；纪念卡 PNG 也换成同一画风。三维场馆只改渲染（纸面平涂、墨线描边、斜排线阴影、纸张颗粒），Blender 模型不变。地址加 `?doodle=0` 可以把三维渲染换回原来的卡通着色，界面不变；浏览器缺少所需的 WebGL2 能力时自动退回原来的渲染。文案、按钮和流程都没有变。
- **字体**：六款字体自托管、从本站同源按需分片下载，没有 CDN：站酷庆科黄油体、霞鹜漫黑、悠哉、龙藏体、得意黑（SIL OFL 1.1）和 Luckiest Guy（Apache 2.0），都按角色改名为「Doodle *」，许可全文随字体发布（`fonts/doodle/LICENSES.txt`），来源、版本与改动见 `THIRD_PARTY_NOTICES.md`。改了界面文字后用 `scripts/fonts/build-doodle-fonts.py` 重新生成（需要 `fonttools` 和 `brotli`），产物入库，不属于 `npm run build`。

这个 Release 的资产是 Node 房间服务运行包，和之前的预发布一样；它带上了新的照片表单与迁移 0013，以及涂鸦风的房间页和它的字体（`dist/event-room/fonts/doodle/`）。示例站不在这个包里：它是另一份构建（CI 产物 `music-space-pages`），按 `docs/deployment.md` 的「静态托管」一节先发到 `/preview/`，用户明确同意后才一次性切换到站点根路径。创建这个 Release 时根路径是否已经切换，以 `docs/PROJECT_STATUS.md` 为准。

这是预发布，不是生产上线。示例站是单设备的浏览器内模拟：换一台设备或另一个浏览器，看到的是各自独立的一份示例，没有二维码、NFC 或邀请链接；同场的角色不是真人。真机（iPhone Safari、Android Chrome）、微信内置浏览器、大陆网络和真实用户都还没有验证；手绘涂鸦风只在桌面 Chrome（含手机尺寸的模拟）上看过。AI 只在公开的演唱会照片上量过，没有在真实观众的手机照片上量过，不当作产品准确率。

升级：迁移 0013 是加法，旧库照常打开；加法迁移不保证任意版本回滚，升级前仍按 `docs/deployment.md` 备份。集成检查与证据写在 `docs/event/evidence/static-pages-qa.md`（尚未生成）；在它写成并逐项通过之前，示例站按未验证处理。
