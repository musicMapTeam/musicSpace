# 长期空间与散场聊天室 · 第一阶段验收

2026-10-02，基于RC.4的feat/community-rooms。新增共享Node/Worker权限引擎event-community.js和加法0007迁移，旧照片、身份、好友与私聊表不重建。长期空间、聊天室、场次成员资格独立。社群最多100名当前成员；房间仍最多24名观众。每页最多50条消息，显式标记实际收到的当前页已读；静音只停止提醒，不删除历史。当前列表最多100个社群，超大规模运营未验收。

散场仍可聊：停止入场/上传不结束已明确加入的聊天室。退出现场失去场次聊天读写，长期社群另行选择加入；退出或房主移出社群即停止该社群读取与发送。恢复后需本人再次加入，并回到安静联系偏好。群聊只文字和回复，不扩展照片访问。拉黑双方的群消息及回复引用被隐藏；作者可撤回，房主可隐藏/移出/恢复资格。既有双向好友私聊不重建。

社群的新招呼要求双方当前成员、明确愿意、未拉黑，并由对方本人接受。当前用主办方已关联的实际场次作为既有关系模型的来源锚点；不要求/伪装双方到场，不因此恢复照片权限，纪念回顾不把社群联系算作该场次认识的人。未关联场次时可以群聊，新招呼会明确提示先关联。

UI沿既有纸签、小人SVG与真实3D场馆；社群成员用各自已保存的小人展示于同一场景。显示社群成员而非在线/实体到场人数，不把上一场照片放入社群。手机抽屉全部可滚动，按钮44px，创建/加入输入在定时刷新时保留，发送草稿与每个独立原请求编号保存在本人浏览器，不把另一标签的待确认请求覆盖。失败重试使用原key，确认结果前不声称已发送。

身份：用户主动制作AES-GCM加密备份，密码在本机派生；恢复绑定实际服务origin，先认证精确身份，采用服务当前profile，明确替换后清理旧私密视图并重载。错误密码、另一来源、撤销、取消或并发身份变更不安装凭据。自动化仅使用合成匿名身份；备份文件/密码不进入截图、Library或Git。无备份清缓存、服务数据被删、遗失密码无法找回。
