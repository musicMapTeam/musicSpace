# 单场房主管理与举报 · 下一切片合同草案

2026-10-01。先审范围与数据边界，当前冻结交换包不含本功能。这里的处理者是创建这一场的房主，没有人工平台审核团队或外部举报服务。

## 第一片能做什么

1. 当前成员可以就本场可见的人或照片提交一条具体反馈给房主；看不到的私藏、定向交换与私聊不进入举报附件
2. 房主查看本场反馈，决定移出本场，或结束处理并说明没有采取移出动作。记录是反馈，不自动认定违规
3. 房主也可从本场成员名单明确选择一人移出。被移出者不能凭原身份重新加入这一场；房主可允许重新申请，但不自动替其入场
4. 举报人可看自己反馈的处理状态、撤回仍待处理的反馈；另一位普通成员无法读举报列表、举报人或处理原因

## 数据与照片权限

- 报告固定 room ID、目标用户 ID，可选本场公开照片 ID、分类和至多 280 字说明；记录提交时目标昵称，避免后来改名让房主处理错人
- 提交前明确“这段说明及目标标识会交给本场房主”。不自动附加私聊文字、私人照片、联系信息、浏览器信息、位置或完整图像副本
- 房主只在普通当前成员照片权限仍成立时查看所指照片。作者撤下、删除、离场或双方屏蔽后，照片仍按原权限拒绝；举报不是额外图片读取权，也不拷贝证据快照绕过撤回
- 房主接口不显示举报人的昵称、avatar 或 ID；后台保留 reporter ID 仅用于本人状态、重复/频率限制和身份校验。不可承诺房主无法从自由文字或现实情境猜到是谁
- 不增加整场私藏、定向交换、私聊、手机号或社交账号读取权。房主离场后的管理只返回其房间、反馈与排除记录的必要元数据，不放宽名单/图片接口
- 举报原因属于未证实反馈，不向全场或被举报者公开展示。本人被移出时只见“房主已将此身份移出本场”，可读自己的照片和历史房间记录

## 移出与恢复

移出事务同时建立本场 exclusion、将成员 left_at 置为当前时间、撤下其照片墙分享、取消其在本场待回应的交换。它不删除本人照片，不撤销已独立接受的双向照片交换，不替任何人屏蔽或移除好友，也不读取私聊。若不想继续个人互动，每个人仍可自行屏蔽或撤销交换。房主确认界面必须说清这一点。

禁止移出自己或房主，其他场次不受影响。排除可撤销，但撤销只恢复“可以申请”，加入仍要求本人明确同意、场次开放和容量检查；不恢复旧照片墙分享、待回应请求或关系。匿名身份换一份可能绕过本场身份排除，这一原型不是现实身份认证或全站封禁系统。

移出与 join/upload/greeting/new exchange 的资格在同一数据库事务检查；拒绝晚到上传或重新加入把被移出的人恢复。执行时重新确认房主角色、目标资格和版本。照片 bytes 仍用既有读后重查；成员快照结束前重新核对 membership。

## 最小接口和迁移

在 `/api/event` 下复用当前认证、幂等和权限事务：

- `POST /rooms/:roomId/reports`：目标、分类、说明、提交同意
- `GET /reports`：仅本人提交记录，分页
- `POST /reports/:id/withdraw`：仅本人仍待处理报告，revision
- `GET /rooms/:roomId/moderation`：仅该房主，反馈/排除分页与必要目标快照
- 后续页分别使用 `GET /rooms/:roomId/moderation/reports?cursor=...` 和 `/exclusions?cursor=...`，每页最多 24 条，游标必须属于本场；排除按不变的创建顺序分页
- `POST /rooms/:roomId/exclusions/:userId`：房主明确移出，可关联报告 ID
- `DELETE /rooms/:roomId/exclusions/:userId`：房主撤销排除，revision
- `POST /reports/:id/resolve`：仅对应房主，明确关闭且是否实际移出，不能随意伪造处理结果

追加 `0005`，旧迁移不改。报告和排除各自 revision；本场身份排除唯一。POST 接收 actor 只能从当前认证取得。报告创建限制每人每场/每小时数量和同目标未结束报告；不能仅凭重复上报数量自动处罚。

移出必须绑定当前名单上的 joinedAt，或绑定一条本场且目标相同的待处理反馈及 revision。恢复申请资格必须有 `allowReentryConsent`；移出有 `removalConsent`。普通结束处理仅允许 `resolution: dismissed`，只有真实移出事务才能将关联反馈标为 resolved。

关于房主本人的投诉不交给房主自审：此片明确拒绝并解释目前没有独立平台申诉渠道，仍可使用个人屏蔽和离场。不能把本地房主反馈功能宣传成完整平台信任与安全体系。

## 验收与停止点

先 Node HTTP/SQLite 与 Worker 合同：A 房主、B 举报人、C 目标、D 局外人。验证精确归属/角色、普通成员/其他房主不能审报告、第三人不能猜记录、无额外图片读取权、作者撤回/删除后的图片拒绝、移出与加入/上传的两种提交顺序、撤销不自动入场、旧幂等回执不恢复成员、同数据重启、旧库字段不变。

之后同一实际网页完成 B 提交→A 读取和明确移出→C 刷新失去场次访问但本人照片保留→A 撤销排除→C 主动重新同意加入。UI 不把“提交给房主”说成平台已审核，不向其他观众展示举报文字。通过这一片再考虑更多管理项。
