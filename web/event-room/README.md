# Music Space · 真实房间入口（本地验收候选）

2026-09-30。路径 `/event-room/`，与旧根站和旧 avatar studio 分开，不是公开发布。

## 本地运行

Node 24 或以上。已有依赖时：

```
npm run build:event
HOST=127.0.0.1 PORT=8787 DATA_DIR=/tmp/musicspace-event-test node server/index.js
```

打开 `http://127.0.0.1:8787/event-room/`。验收运行包已带内联 HTML，无需 npm install。Node 默认只监听回环地址，不改防火墙或网络设置。

## 这次接通的范围

真实匿名身份 → 主办方开房并明确加入 → 邀请码/二维码 → 独立观众明确加入 → 成员名单与三维角色 → 上传照片时明确选择私藏或分享给本场 → 收回/移除 → 离场及本人保留库。

- UI 只显示实际 API 返回的成员，不植入虚构观众
- 近处手机最多展示4位、桌面最多8位，完整同场名单保留全部成员
- 新建身份目前采用已单独检查的一个精修造型，可选肤色、发色、上衣色和有无眼镜。旧复杂头像按原组件渲染，不能将其伪称为这一款新模型
- 表单、名单、照片在 WebGL 不可用时仍能使用；不以平面场景伪装 WebGL
- 私密照片不进入墙面。墙面只用当前成员权限允许读取的 Blob，缓存与模型贴图在换房/失效/权限撤回后撤下
- 可见页面每5秒刷新，出错退避到30秒，后台停止；这不是实时 presence 或入场认证
- 上传草稿保存在当前浏览器；实际上传要点保存。存储不足明确警告无法保证刷新恢复
- 丢包后保留原操作及目标，重试不会默认改用新内容。失效身份不会被自动新建身份取代

## 当前开发候选：分层小人、实时衣橱与文字私聊

2026-09-30 15:03 UTC 用户明确允许二维角色进入三维场景。当前入口使用自包含原生 SVG 的四方向立绘，场馆仍为实际 Three.js 几何与透视机位。不是3D人物，也不是整幅背景贴图。

衣橱包含36件独立部件（8发型、6眼镜含无、6上衣、6下装、4鞋、6配饰含无），另有4表情、4姿势和原颜色选项。试穿时可转看四方向；六套只是起始搭配。未点保存，不向资料API提交；保存更新既有身份，不新建一个同名账号。已提交保存不能通过取消撤回；结果未知保留原操作重试。

私聊入口在「招呼与朋友」和已互相接受的朋友卡内。只能发文字，无附件、链接预览或在线状态。默认每4秒读取已打开且可见的对话，不是推送或在线认证。「已保存」只表示服务器确认，不代表对方已读；「已读」仅来自实际可见消息的明确确认。移除或屏蔽后不能发新文字，双方可读本人既往对话；对方新资料/新的已读状态不会泄漏。文字存于本地运行服务，本轮没有端到端加密或云端部署声明。

新增 `0003_event_chat.sql` 和 `event-chat.js` 必须随便携包提供。最新构建和代码测试不等于已经通过GPU/真实浏览器。本轮独立视觉QA包的HTML哈希为 `2babdf2a41cbde51d445b87eaeec6fdd8ff610e781fe2d65d8832f6a5064d9fb`，它不含私聊UI；后续集成版另行记录。
