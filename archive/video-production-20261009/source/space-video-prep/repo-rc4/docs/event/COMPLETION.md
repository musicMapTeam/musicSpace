## 当前功能切片：快速入场 → 这一晚 → 下一次真实入场

实际两独立浏览器界面流程已验证，证据 `libfile_bce753e909a88191bb10ab500528fc77`。详细边界见 [实际验收记录](evidence/event-loop-browser-qa.md)。这不是生产完成或留存研究结论。

1. 邀请页缺身份时，只需昵称即可使用默认小人；换装作为自选入口。当前场次与“同意让本场成员看到昵称和小人”仍必须明确显示。建立身份成功而加入失败时保留身份，不假报已经入场；重试仍使用原操作
2. 按一个真实历史场次聚合回顾：本人在该场次的未删除照片、目前仍可读的共享图、在本场建立且目前仍有效的双向联系。旧成员资格不是查看别人照片的授权。离场/撤回/删除/屏蔽必须即时收掉相应信息
3. 共享图片和朋友列表按场次分页，不把全局第一页筛选后当作完整数量。过期读响应不能覆盖后选场次，切身份立即清掉回顾缓存和图片对象 URL
4. 回顾后可输入新的真实邀请码、继续已有且仍有权限的现场，或自己开一场。不编造未来活动和朋友出席，不外联或发通知
5. 两独立用户做开场、快速加入、分享、认识、结束/离场、回顾、下一场；加入中断、重复点击、撤回/屏蔽、切场次和重启必须覆盖
