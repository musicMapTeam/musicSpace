# 定向照片交换 · 客户端候选

2026-10-01。已接入当前本地房间入口，尚待真实浏览器双身份验收。

从另一人的本场照片详情选择交换，再选本人在同场的一张照片。界面从选中的受保护原图生成 320px / 32KiB 以内的小图，发送者审阅两张具体图后同意预览和接受后的原图访问。接收者看到对方小图与自己将提供的指定原图，明确同意后才开放本次两张原图。选择照片、打开面板和勾选本地选项均不会自动发送。

交换独立于照片墙与朋友关系。界面分别提供从墙收回、撤销本次交换、收回一张照片的全部分享。离场回顾有独立的交换入口，不把这些照片自动加入本人图库或原照片墙集合。接受、撤销、删除、屏蔽的准确范围在操作前显示；已下载副本不能远程收回。

## 源层验证

客户端测试使用真实 Node HTTP + SQLite 独立身份，覆盖固定两图、第三人隔离、预览与原图区分、接受、离场后访问、撤销、双击、不同内容不能改写已冻结操作、丢失提交回应后同键重试、旧 accepted 回执不复活授权、提交已确认但 canonical GET 失败、延迟图片/列表、身份切换恢复、存储拒绝、伪造本地 actor 和并发结果。

独立审阅进一步复现并收口：

- 原 POST 结果未知时，重试前的 GET 失败不能把它改成可丢弃失败；原 POST 的明确业务拒绝可以结束不确定
- 每个操作使用独立 localStorage 项，两标签并发不会通过覆盖共享 JSON 丢掉彼此原键；不是跨设备账号恢复功能
- 每次异步结果返回自身的操作回执，不借用较新操作的 lastResult
- 读到历史幂等回执后必须 GET 当前权限；读取失败时只承认操作已收到，不显示新的授权照片

DOM 绑定测试核对照片详情准确目标、三种分享控制和全部收回的前后图片失效。构建通过。UI 中的图片、滚动、同意选择、真实断网和两独立浏览器流程仍由下一轮实际 QA 确认，不能由源码测试替代。

## 仍有明确边界

预览由客户端生成，服务端只校验结构/大小/声明尺寸，不比对预览与原图像素。终态请求的小图仍保存在私有存储但不能读取；物理清理政策尚待产品收口。当前并非已公开的新服务，不声称生产级、实体双手机或负载测试通过。
