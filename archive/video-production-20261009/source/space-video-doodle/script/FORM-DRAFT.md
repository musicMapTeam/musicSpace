### 每句话的依据，以及刻意不写的

| 写了 | 依据 |
|---|---|
| 痛点三句（只有自己那个角度、最好看的那张在陌生人手机里、还没认识就走散） | 团队对场景的判断，不是调研数据；不写成数据 |
| 群相册分不清哪几张是同一刻 | 同上（团队判断）；产品用拍摄时间解决的正是这件事 |
| 同场观众带着手绘小人进入同一个三维 Livehouse 房间 | 事件房间页：三维场馆 + 二维手绘小人（README「已实现的产品体验」；示例站里亲自走过） |
| 把照片放上墙，交换「同一刻的另一面」 | 照片墙、「同一刻的另一面」标记、「和 TA 交换这个视角」 |
| 端侧 AI 在浏览器里建议照片视角（舞台／人海／身边／细节），照片不上传，没把握就说不确定 | 上传表单原文「AI 在本机判断，照片不上传，没把握就不替你选」；「不确定，请选择」；TinyCLIP-ViT-8M/16 图像塔 + onnxruntime-web，本站同源加载（关于这个示例） |
| 规则按照片自带的拍摄时间，把相差 3 分钟内的照片配成同一刻 | 「按拍摄时间分组（相差不超过 3 分钟），规则判断，不是 AI」；EXIF `DateTimeOriginal` |
| 交换须双方本人同意 | 「我同意提供选中照片的预览…」+「等待本人回应」→「交换已接受」 |
| 招手交友、私聊、专辑世界杯、默契局、纪念卡 | 示例站里都走过（SHOTS.md 第 3 节） |
| 在线 Demo 在浏览器里运行，同场角色是标明「示例」的虚构角色（B 版） | 关于这个示例：「房间服务就运行在你的浏览器里…没有服务器，没有账号，什么都不会上传」「都是虚构的，由这个页面自动回复，不是真人」 |

不写：AI 准确率（只在公开照片上量过，不能当产品准确率）、「AI 配对/匹配」（配对是规则）、真实用户或上线、真机/微信/大陆网络的表现（没验证过）、跨设备交换（线上示例是单个浏览器）、「照片永远不会离开设备」（房间版保存时会上传到房间服务；示例站里什么都不上传 — 两件事分开说，介绍里只说 AI 判断时不上传）、与 QQ音乐 / 酷狗 的任何对接。

### 如果表单另有「AI 使用说明」

- 产品里只有一个模型：TinyCLIP-ViT-8M/16 的图像塔（MIT，int8，8.8 MB）+ onnxruntime-web（WASM），在浏览器里建议照片视角，只是建议，可以说「不确定」，选择由人做；模型、运行时和标签从本站同源加载，首次约 10 MB。
- 不是模型：拍摄时间（EXIF）、「同一刻」分组与配对、排序与理由、示例角色的自动回应，都是普通规则。
- 素材：示例照片是 2026-09-26 用 AI 生成的两张虚构演唱会图及其裁切（`web/assets/image-provenance.json`）；视频配乐为〔团队原创 / CC0 曲目，见授权留档〕。
