# Music Space 0.22.0-rc.2 — 完整产品的文案：一句披露，社群面向 Livehouse，音乐探索换上涂鸦风 预发布

这一版不加功能，改的是产品怎么说话，以及音乐探索的样子。用户 2026-10-07 的两条要求：「去掉那些说明性文字，这个产品必须是完整的」，以及开房的一方和长期社群面向 Livehouse 场地；同一天用户还决定保留 Music Map，统一进产品，叫「音乐探索」。约束原文在 `AGENTS.md` 顶部 2026-10-07 一节，逐条改动见 `CHANGELOG.md` 的 0.22.0-rc.2。

- **一句披露**：界面读起来是一个完整的产品，不再处处解释或替自己开脱。全产品只在「关于 Music Space」的「在线版」一节说一句「在线版里的场地、观众和照片是演示内容，观众会自动回复。」；其余地方没有「示例」「虚构」「模拟」「演示」「自动回复」这类字样，也没有「不代表……」「原件仍归各自」「无法远程收回」「规则判断，不是 AI」之类的小字。同意的勾选框都在，写成一句短的第一人称；提示、按钮和报错都改短。
- **Livehouse**：「我是 Livehouse / 主办方，开个房」；场地为每一场演出开一个房间，散场后乐迷留在「Livehouse 乐迷社群」里，「下一场预告」发在那里。在线版的种子场次「回声现场」（月台 Livehouse）已经关联「月台 Livehouse 乐迷社群」，里面有下一场预告。
- **在线版做不到的不摆出来**：在线版的世界只在一个浏览器里，所以那里不显示「身份备份与恢复」和社群邀请码 / 邀请链接；现成照片和「把拍摄时间设成 21:47」只在种子场次的房间里出现，访问者自己开的房间没有。救援提示只剩「重新载入」「重新开始」。
- **角色**：阿遥、小满、北屿、林间不再带「·示例」后缀；台词对任何访问者都成立，私聊说到「下次月台见！」就停；朋友邀请「双人纪念」时，角色会加入、写上自己那一面并确认同一版本，纪念图 PNG 能做出来。
- **音乐探索**：`/music-map/` 的页面留下来，界面和三维小院换成和现场同一套手绘涂鸦风（小院用现场同一个涂鸦渲染，地址加 `?doodle=0` 换回旧的卡通着色），说明性文字去掉，每首合唱的出处收进「来源」按钮，「关于音乐探索」里有一节「数据来源」。0.15 的虚构示例目录删掉了，真实合唱目录（29 位音乐人、37 首）和出处不变；图标改成自绘的，页面不再带 Phosphor 的许可。
- **Node 房间版**：共用的文字一起改短，但对真实房间仍然属实（保存时才上传照片、「服务器已确认」）；房间服务的部分报错换成同一套用词（「小人」「身份已失效，请刷新页面」「邀请码不对，请检查后再试。」等），错误码不变。社群邀请链接复制成功后提示「邀请链接已复制」。

这个 Release 的资产仍是 Node 房间服务运行包；房间服务的规则、数据格式和迁移与 0.22.0-rc.1 相同，没有新迁移。在线版（GitHub Pages 的静态站）是另一份构建（CI 产物 `music-space-pages`），按 `docs/deployment.md` 的「静态托管」一节发布；存着上一版世界的浏览器打开新版本时会自愈一次，提示「现场已更新」。

这是预发布，不是生产上线。在线版是单设备的浏览器内运行：同场的人是自动回应的角色，不是真人；换一台设备或另一个浏览器，看到的是各自独立的一份。真机（iPhone Safari、Android Chrome）、微信内置浏览器、大陆网络和真实用户都还没有验证；手绘涂鸦风只在桌面 Chrome（含手机尺寸的模拟）上看过。检查范围与结果写在 `docs/PROJECT_STATUS.md`。
